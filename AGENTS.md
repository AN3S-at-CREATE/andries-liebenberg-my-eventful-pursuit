# AN3S agent instructions

## Design system — all editors
The only source for colours, fonts, radii, glows, gradients, logos and icons is [AN3S-CREATE/an3s-design-system](https://github.com/AN3S-CREATE/an3s-design-system), published as a Claude Design System. Follow its brand book (`project/README.md`): pink leads, cyan answers, deep-space grounds, Montserrat, light rather than drop shadows. Read `src/design-system/README.md` before UI work.

- Never edit generated `src/design-system/`. Change the upstream system, run `node tools/export.mjs` there, then `npm run ds:sync` here (`--from <path>` if not at `../Design Sytsem AN3S`). Missing tokens belong upstream first.
- Use preset classes, CSS variables or `@/design-system/tokens` (including charts/canvas/PDF). No stock Tailwind colours, raw hex/rgb/hsl/named colours, arbitrary colours, font families/shorthands, `@font-face` or font-host URLs. This includes custom properties, JSX/styles and code setters (`ctx.fillStyle/font`, `el.style`, `setProperty`, `setAttribute`, `addColorStop`, jsPDF colour setters). Build code values from tokens, e.g. ``ctx.font = `600 14px ${font.sans}```. Never redeclare DS variables, including via `@property`.
- `primary` is pink (`pink-glow` for words/fills); `secondary` is cyan (`cyan-glow`). Edges, glows and charts use saturated `pink/cyan/blue/violet`, never role tints: `border-pink/35`, `shadow-cyan/25`, `hsl(var(--pink-hsl) / 0.4)`. Focus uses `ring-ring`; controls use `border-input` (`line-strong`). Helper/options names use roles (`glow-primary`, `glass-secondary`, `glow="primary"`). `destructive` maps to `danger`, `success` to `success`; include a word or icon.
- Logos/icons use DS assets. Brand-named images (favicon/app icon/logo/wordmark/AN3S) and icons linked by HTML/manifests must be exact asset copies. Legacy exceptions are content-pinned in `LEGACY_BRAND_ASSETS` in `scripts/check-design-system.mjs`: don't alter them; remove entries when files go. Client logos/event photos resembling brand files need `NOT_BRAND_ASSETS` entries with reasons. Share images, JSON-LD logos and code-drawn logos aren't checked yet but still follow the brand rules.
- Run `npm run check:ds` before finishing; CI runs it on PRs. Justified exceptions need `ds-allow: <reason>` on/above the line. Commit real files, not symlinks under `src/`, `public/` or at `index.html`/`tailwind.config.ts`. Checker maintenance details live in `scripts/AGENTS.md`; content rules in `src/AGENTS.md`.

## Development
## Approved visual motion exception
- Only one-time scroll fade-and-rise (10px, approximately 500ms ease-out, no scale), slow drifting hero stars, a breathing halo behind the static wordmark, and interactive edge glow with at most 2px lift are permitted. No scroll-linked parallax, flicker, scroll hijacking or other motion. This is the complete approved exception, not permission for general animation.
- Hero media may autoplay muted, loop and playsinline with its poster and a deep-space contrast overlay. Reduced-motion visitors see only the poster; reduced motion disables fades, drift, halo animation and lifts. Functional loading spinners remain enabled outside reduced motion.
- Home media is owned by HomeHero and unmounts off home; HeroMedia accepts an explicit film source and never substitutes unrelated footage, preventing arrival and nebula films from being swapped. Non-home media must live outside route elements to preserve playback across navigation.
- Shared Section and CardGrid components own page rhythm and equal-height card layout; this prevents layout drift between routes. Work and proof views read roles/evidence from facts.ts and never infer missing proof.

Single Vite + React + TypeScript SPA, hosted Supabase, no monorepo/local backend required. Commands are in `package.json`: dev on localhost:8080 (fixed by Vite config), lint, build, preview, test. Vitest covers company-card stretch; run relevant tests and preview checks for layout changes. Do not assume historical lint warnings describe current results.

- Follow the current environment's package-manager instructions. Historically `.jules/*` and `plan.md` used `pnpm install --frozen-lockfile`; multiple lockfiles exist, so avoid desynchronising them. Ignored esbuild/SWC/core-js install scripts need no interactive `pnpm approve-builds`.
- Dev esbuild may reject duplicate named imports that production SWC silently dedupes. For blank pages, check console duplicate-declaration errors before blaming the environment. For corrupt/stale optimized dependencies, clear `node_modules/.vite` and restart only when the environment allows it.
- Most content is client-rendered and works offline. ROI Calculator is currently hidden on Home. Concierge, Performance Brief and contact email require hosted Supabase Edge Functions configured by `VITE_SUPABASE_*` (anon key). Server secrets (`LOVABLE_API_KEY`, `RESEND_API_KEY`, service-role key) live in Supabase, unnecessary for general frontend work. Local edge work needs Supabase CLI and Deno, not installed by default.
